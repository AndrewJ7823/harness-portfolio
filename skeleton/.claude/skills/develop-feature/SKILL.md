# develop-feature (축약판)

> 포트폴리오용 축약판이다. 실제 스킬의 단계별 세부 지시·판정 기준은 뺐다.

이 스킬은 절차를 **실행하는 오케스트레이터**다. "무엇을 어떤 순서로"는 절차 문서가 정본이고, 스킬은 상태 전이·승인 게이트·기록 작성을 얹는다.

## 단계

0. **안전 확인** — 이 기능이 발송·외부 연동을 포함하는지 먼저 판별한다.
1. **입력 해석** — 티켓이면 조사, 기능 설명이면 기존 티켓 확인 후 생성 여부를 묻는다. 에러 링크면 조사 → 생성 여부 확인 → 생성.
2. **스펙 작성** — 요약을 먼저 쓰고, 케이스는 정상 / 분기 / 경계 / 에러·권한 / 동시성 축으로 전수 열거한다. **케이스 열거는 하위 에이전트에 위임하지 않는다.**
3. **독립 반박 검토** — `spec-reviewer`를 호출하고, 지적마다 반영하거나 비채택 근거를 남긴다.
4. **승인 게이트** — 요약(케이스 수 · 데이터 변경 · 외부 의존 · 검토 지적/반영)을 보여 주고 멈춘다. "스펙 승인"이 있어야 다음 단계.
5. **구현** — 케이스 ID를 이름에 넣은 테스트를 먼저 쓰고(실패 확인) 구현한다.
6. **검증** — `/verify-feature`를 되묻지 않고 이어서 실행한다. PASS가 아니면 고치고 다시.
7. **기록** — 판단 필드만 기록하고 지표 한 줄을 남긴다. 트래커 → review.
8. **보고** — diff 검토를 요청하고 "커밋해줘"를 기다린다.
